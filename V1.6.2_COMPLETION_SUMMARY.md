## 🐛 Issues Fixed

### 1. "Select Plan" Button Not Responding
**Problem:** Clicking "Выбрать план" button did nothing for new users
**Root Cause:** `teamId` check blocked execution when no subscription existed
**Solution:** Added `effectiveTeamId` fallback logic using MyTeams query

**Files Modified:**
- [apps/web/src/packages/components/settings/SubscriptionManagement.tsx](apps/web/src/packages/components/settings/SubscriptionManagement.tsx)

### 2. Team ID Resolution Error
**Problem:** "Не удалось определить команду" error appeared
**Root Cause:** `teamId` was undefined for new users without subscriptions
**Solution:** Added cascade fallback: `prop → subscription.teamId → teams[0].id`

**Files Modified:**
- [apps/web/src/packages/components/settings/SubscriptionManagement.tsx](apps/web/src/packages/components/settings/SubscriptionManagement.tsx)

### 3. Prisma Validation Error
**Problem:** `Argument 'plan' is missing` database error
**Root Cause:** Backend didn't properly map `planData.slug` to legacy `plan` enum
**Solution:** Added automatic slug-to-enum conversion (lite→LITE, foreman→FOREMAN, brigade→BRIGADE)

**Files Modified:**
- [apps/api/src/modules/subscriptions/subscriptions.service.ts](apps/api/src/modules/subscriptions/subscriptions.service.ts:130-138)

### 4. Payment Provider Not Found
**Problem:** "Stripe provider not configured" and "Subscription already exists" errors
**Root Cause:** PaymentProvider table was empty in database
**Solution:** Created multiple setup options (pnpm script, SQL files, manual)

**Files Created:**
- [apps/api/prisma/seed-payment-providers.ts](apps/api/prisma/seed-payment-providers.ts)
- [apps/api/prisma/setup-payment-providers.sql](apps/api/prisma/setup-payment-providers.sql)
- [apps/api/prisma/cleanup-duplicate-subscriptions.sql](apps/api/prisma/cleanup-duplicate-subscriptions.sql)
- [QUICK_FIX.md](QUICK_FIX.md)

### 5. **Payment Provider Async Initialization** (NEW)
**Problem:** "Stripe provider not initialized" error when trying to create payment
**Root Cause:** Both `StripeProvider` and `YookassaProvider` called async `initializeClient()` in constructor without await, causing providers to not be initialized when `createPayment()` was called
**Solution:**
- Made `initializeClient()` synchronous, loading from env vars first
- Added `ensureInitialized()` async method for lazy loading from SystemSettings
- Updated all provider methods to call `ensureInitialized()` before use
- Added development mode mock implementations for both providers

**Files Modified:**
- [apps/api/src/core/payments/providers/stripe.provider.ts](apps/api/src/core/payments/providers/stripe.provider.ts:42-126)
- [apps/api/src/core/payments/providers/yookassa.provider.ts](apps/api/src/core/payments/providers/yookassa.provider.ts:42-127)

### 6. **Development Mode Mock Implementation** (NEW)
**Problem:** Cannot test subscription UI flow without real Stripe/Yookassa API credentials
**Solution:** Added mock payment implementations for development environment
- When providers detect missing credentials in development mode, they return mock payment data
- Mock payments redirect to return URL with query parameters: `?mock=true&provider=stripe&amount=XXX`
- Allows full UI flow testing without requiring payment gateway setup
- Production mode still requires real credentials and throws errors if missing

**Features:**
- Mock payment IDs: `mock_stripe_TIMESTAMP` or `mock_yookassa_TIMESTAMP`
- Mock expiration: 30 minutes from creation
- Warning logs indicate when running in mock mode
- Automatically disabled in production (`NODE_ENV=production`)

**Files Modified:**
- [apps/api/src/core/payments/providers/stripe.provider.ts](apps/api/src/core/payments/providers/stripe.provider.ts:118-127)

## ✨ New Features

### Automatic Payment Provider Selection

**Feature:** IP-based geolocation determines payment provider automatically

**How It Works:**

1. User clicks "Выбрать план" (Select Plan)
2. Backend extracts user's IP from request headers
3. Geolocation utility determines country from IP
4. Provider auto-selected:
   - Russia, Belarus, Kazakhstan, etc. → **Yookassa** (Primary)
   - Ukraine, Europe, USA, etc. → **Stripe** (Secondary)
5. User redirected directly to payment page (no manual selection modal)

**Files Created:**
- [apps/api/src/modules/payments/utils/geo-provider.util.ts](apps/api/src/modules/payments/utils/geo-provider.util.ts) - IP detection and country mapping

**Files Modified:**
- [apps/api/src/modules/payments/payments.resolver.ts](apps/api/src/modules/payments/payments.resolver.ts:25-34) - IP extraction from request context
- [apps/api/src/modules/payments/payments.service.ts](apps/api/src/modules/payments/payments.service.ts:45-52) - Auto-provider selection

## ⚠️ Required Setup Steps

### 🔴 CRITICAL: You Must Complete These Steps Before Testing

The database needs payment provider records to work. Choose ONE of the following options:

### Option 1: pnpm Script (Recommended)

```bash
# 1. Start database
docker compose up -d postgres

# 2. Wait 10 seconds for DB to start

# 3. Run provider seed
cd apps/api
pnpm prisma:seed:providers
```

### Option 2: SQL Files

```bash
# Start database
docker compose up -d postgres

# Run SQL scripts
psql -h localhost -p 5433 -U prorab -d prorab -f apps/api/prisma/setup-payment-providers.sql
```

Password: `prorab`

### Option 3: Prisma Studio (Manual)

```bash
cd apps/api
pnpm prisma:studio
```

Then manually create two PaymentProvider records (see [QUICK_FIX.md](QUICK_FIX.md) for details).
