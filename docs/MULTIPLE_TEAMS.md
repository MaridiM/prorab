# 👥 Множественные команды - Как это работает

## 🎯 Концепция

В ProRab пользователь **может быть участником нескольких команд одновременно**.

### Роли пользователя

1. **Владелец (Owner):**
   - Может создать неограниченное количество своих команд
   - Имеет полный контроль над своими командами
   - Может приглашать участников в свои команды
   - Не может быть владельцем чужих команд

2. **Участник (Member):**
   - Может быть приглашен в любое количество команд
   - Имеет доступ к проектам команды
   - Не может управлять настройками команды
   - Может быть участником команды, даже если у него есть своя команда

## 📊 Структура данных

### User → Teams (Множественные отношения)

```prisma
model User {
  id              String   @id
  
  // Команды где пользователь - владелец (может быть много)
  ownedTeams      Team[]   @relation("TeamOwner")
  
  // Команды где пользователь - участник (может быть много)
  memberships     TeamMember[]
  
  // Текущая активная команда (одна)
  currentTeamId   String?
  currentTeam     Team?    @relation("CurrentTeam")
}

model Team {
  id        String   @id
  ownerId   String   // Владелец (один)
  
  owner     User     @relation("TeamOwner")
  members   TeamMember[]  // Участники (много)
}

model TeamMember {
  id       String   @id
  teamId   String
  userId   String
  role     String   // "owner" или "member"
  
  @@unique([teamId, userId])  // Один пользователь = один раз в команде
}
```

## 🔄 Сценарии использования

### Сценарий 1: Пользователь имеет свою команду и его приглашают в другую

**Пример:** Иван создал команду "Бригада Иванова" и является её владельцем. Петр приглашает Ивана в свою команду "Строй Сервис".

**Что происходит:**

```
До приглашения:
┌─────────────────────────────────────────┐
│ Иван (ID: user-123)                     │
├─────────────────────────────────────────┤
│ Владелец:                               │
│   ✅ "Бригада Иванова" (team-456)       │
│                                         │
│ Участник:                               │
│   (нет)                                 │
└─────────────────────────────────────────┘

После приглашения:
┌─────────────────────────────────────────┐
│ Иван (ID: user-123)                     │
├─────────────────────────────────────────┤
│ Владелец:                               │
│   ✅ "Бригада Иванова" (team-456)       │
│                                         │
│ Участник:                               │
│   ✅ "Строй Сервис" (team-789)          │
│      role: "member"                     │
└─────────────────────────────────────────┘
```

**Результат:**
- ✅ Иван остается владельцем своей команды
- ✅ Иван становится участником команды Петра
- ✅ Иван видит обе команды в списке `myTeams`
- ✅ Иван может переключаться между командами

```
После приглашения:
```

### Сценарий 3: Новый пользователь без команды принимает приглашение

**Что происходит:**

```
├─────────────────────────────────────────┤
│ Владелец:                               │
│   (нет)                                 │
│                                         │
│ Участник:                               │
│   ✅ "ПроСтрой" (team-333)              │
│      role: "member"                     │
└─────────────────────────────────────────┘
```

**Результат:**
- ✅ Алексей пропускает онбординг
- ✅ Алексей сразу попадает в команду
- ✅ Алексей может позже создать свою команду
- ✅ После создания своей команды будет иметь 2 команды

## 💾 Backend Implementation

### GraphQL Query: myTeams

```typescript
@Query(() => [Team])
@UseGuards(AuthGuard)
async myTeams(@CurrentUser() user: { id: string }): Promise<Team[]> {
  return this.teamsService.getMyTeams(user.id)
}
```

### Service: getMyTeams

```typescript
async getMyTeams(userId: string): Promise<Team[]> {
  return this.prisma.team.findMany({
    where: {
      OR: [
        // Команды где пользователь является владельцем
        { ownerId: userId },
        // Команды где пользователь является участником
        {
          members: {
            some: {
              userId,
            },
          },
        },
      ],
    },
    orderBy: {
      createdAt: 'desc',
    },
  })
}
```

**Важно:** Метод возвращает ВСЕ команды пользователя:
- ✅ Команды где пользователь является владельцем (`ownerId === userId`)
- ✅ Команды где пользователь является участником (есть запись в `TeamMember`)

### Проверка дублей при приглашении

```typescript
async joinTeamByInvite(userId: string, code: string) {
  // ...
  
  // Проверяем что пользователь ещё не в команде
  const existingMembership = await this.prisma.teamMember.findUnique({
    where: {
      teamId_userId: {
        teamId: inviteCode.teamId,
        userId,
      },
    },
  })
  
  if (existingMembership) {
    throw new BadRequestException('Вы уже состоите в этой команде')
  }
  
  // Создаём нового участника
  await this.prisma.teamMember.create({
    data: {
      teamId: inviteCode.teamId,
      userId,
      role: 'member',  // Всегда member при приглашении
    },
  })
}
```

## 🧪 Тестовые сценарии

### Позитивные

1. ✅ Пользователь с командой принимает приглашение в другую команду
2. ✅ Пользователь без команды принимает приглашение
3. ✅ Участник одной команды принимает приглашение во вторую
4. ✅ Владелец нескольких команд видит все свои команды
5. ✅ Пользователь может создать команду после присоединения
6. ✅ Переключение между командами работает корректно

### Негативные

1. ❌ Повторное приглашение в ту же команду → "Вы уже состоите в этой команде"
2. ❌ Попытка стать владельцем чужой команды → невозможно
3. ❌ Удаление команды где пользователь участник → пользователь остается с другими командами

## 🎯 Важные моменты

### ✅ Что можно делать:

- Быть владельцем нескольких команд
- Быть участником нескольких команд
- Иметь свою команду И быть участником чужих
- Переключаться между командами
- Создать новую команду в любой момент

### ❌ Что нельзя делать:

- Состоять в одной команде дважды (unique constraint)
- Быть владельцем чужой команды
- Передать владение команды (пока не реализовано)

### 💡 Рекомендации:

1. **Для владельцев:** Создавайте отдельные команды для разных направлений бизнеса
2. **Для участников:** Можете работать в нескольких бригадах параллельно
3. **Для подрядчиков:** Создайте свою команду + принимайте приглашения от заказчиков
