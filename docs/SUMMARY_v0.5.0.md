# 📋 Резюме: ProRab v0.5.0 - Множественные команды и улучшения

## 🎯 Главный вопрос: Что если пользователь уже имеет бригаду?

### ✅ Ответ: Это нормально! Пользователь может быть в нескольких командах

## 🏗️ Как это работает


### База данных

```prisma
model User {
  id              String
  
  // МОЖЕТ БЫТЬ ВЛАДЕЛЬЦЕМ НЕСКОЛЬКИХ КОМАНД
  ownedTeams      Team[]         @relation("TeamOwner")
  
  // МОЖЕТ БЫТЬ УЧАСТНИКОМ НЕСКОЛЬКИХ КОМАНД
  memberships     TeamMember[]
  
  // Текущая активная команда (для UI)
  currentTeamId   String?
  currentTeam     Team?          @relation("CurrentTeam")
}

model TeamMember {
  teamId   String
  userId   String
  role     String  // "owner" или "member"
  
  @@unique([teamId, userId])  // Нельзя дважды в одной команде
}
```

## 📊 Возможные сценарии

### Сценарий А: Владелец + Владелец

**Ситуация:** Иван владеет "Бригадой Иванова", создает вторую команду "Ремонт Плюс"

```
Иван:
├─ 👑 Владелец: "Бригада Иванова"
└─ 👑 Владелец: "Ремонт Плюс"
```

**Результат:** ✅ Можно владеть неограниченным количеством команд

### Сценарий Б: Владелец + Участник (ВАША СИТУАЦИЯ)

**Ситуация:** Иван владеет "Бригадой Иванова", Петр приглашает его в "Строй Сервис"

```
До приглашения:
Иван:
└─ 👑 Владелец: "Бригада Иванова"

После приглашения:
Иван:
├─ 👑 Владелец: "Бригада Иванова"  ← сохраняется!
└─ 👤 Участник: "Строй Сервис"     ← добавляется!
```

**Результат:** ✅ Можно быть владельцем своей команды И участником чужих

### Сценарий В: Участник + Участник

**Ситуация:** Мария участник "Ремонт Плюс", её приглашают в "Строй Мастер"

```
До приглашения:
Мария:
└─ 👤 Участник: "Ремонт Плюс"

После приглашения:
Мария:
├─ 👤 Участник: "Ремонт Плюс"    ← сохраняется!
└─ 👤 Участник: "Строй Мастер"   ← добавляется!
```

**Результат:** ✅ Можно быть участником неограниченного количества команд

### Сценарий Г: Новый пользователь → Участник

**Ситуация:** Алексей зарегистрировался по приглашению в "ПроСтрой"

```
Алексей (новый):
└─ 👤 Участник: "ПроСтрой"

Через месяц создает свою команду:
Алексей:
├─ 👑 Владелец: "Алекс Строй"  ← создал свою!
└─ 👤 Участник: "ПроСтрой"     ← остался участником!
```

**Результат:** ✅ Можно создать свою команду в любой момент

## 🔒 Что происходит при приглашении

### Backend логика (`joinTeamByInvite`)

```typescript
async joinTeamByInvite(userId: string, code: string) {
  // 1. Находим приглашение
  const inviteCode = await findInviteCode(code)
  
  // 2. Валидация
  if (!inviteCode) throw Error('Код не найден')
  if (inviteCode.usedBy) throw Error('Код уже использован')
  if (inviteCode.expiresAt < now) throw Error('Код истёк')
  
  // 3. ПРОВЕРКА ДУБЛЕЙ (важно!)
  const alreadyMember = await prisma.teamMember.findUnique({
    where: {
      teamId_userId: {
        teamId: inviteCode.teamId,
        userId: userId
      }
    }
  })
  
  if (alreadyMember) {
    throw Error('Вы УЖЕ состоите в этой команде')
  }
  
  // 4. Создаем НОВУЮ роль member
  await prisma.teamMember.create({
    data: {
      teamId: inviteCode.teamId,
      userId: userId,
      role: 'member'  // ВСЕГДА member при приглашении
    }
  })
  
  // 5. Отмечаем код как использованный
  await prisma.inviteCode.update({
    where: { id: inviteCode.id },
    data: {
      usedBy: userId,
      usedAt: new Date()
    }
  })
  
  // ✅ Пользователь добавлен в команду
  // ✅ Существующие роли НЕ изменились
  // ✅ Может переключаться между командами
}
```

## 📱 Практические примеры

### Пример 1: Подрядчик работает на несколько заказчиков

```
Сергей (прораб):
├─ 👑 Владелец: "Бригада Сергея"     ← его своя команда
├─ 👤 Участник: "ГлавСтрой"          ← работает на заказчика 1
├─ 👤 Участник: "СтройКомплект"      ← работает на заказчика 2
└─ 👤 Участник: "Ремонт Премиум"     ← работает на заказчика 3
```

**Преимущества:**
- Ведет свою бригаду
- Видит проекты всех заказчиков
- Отслеживает оплату от разных команд
- Может работать параллельно на нескольких объектах

### Пример 2: Бригадир имеет несколько бригад

```
Михаил (владелец):
├─ 👑 Владелец: "Отделка Премиум"    ← основная бригада
├─ 👑 Владелец: "Электрика Плюс"     ← специализированная бригада
└─ 👑 Владелец: "Сантехника PRO"     ← еще одна специализированная
```

**Преимущества:**
- Разделение по специализациям
- Отдельная бухгалтерия для каждой бригады
- Разные участники в каждой команде
- Гибкое управление проектами

### Пример 3: Работник в нескольких бригадах

```
Андрей (электрик):
├─ 👤 Участник: "Бригада Иванова"
```

**Преимущества:**

## ❌ Что НЕЛЬЗЯ делать

### 1. Состоять в команде дважды

```
❌ НЕВОЗМОЖНО:
Иван:
├─ 👤 Участник: "Строй Сервис" (роль 1)
└─ 👤 Участник: "Строй Сервис" (роль 2)  ← Дубль!

Unique constraint teamId_userId предотвращает это
```

### 2. Быть владельцем чужой команды

```
❌ НЕВОЗМОЖНО:
Иван создал команду "Бригада Иванова"
ownerId: user-123 (Иван)

Петр НЕ может стать вторым владельцем этой команды
Только роль "member" доступна через приглашение
```

### 3. Удалить себя если ты владелец

```
❌ НЕВОЗМОЖНО:
Иван (owner) → удалить себя из "Бригада Иванова"

Владелец не может удалить себя
Нужно сначала передать владение (пока не реализовано)
```

## ✅ Итого

### Главные правила:

1. **Пользователь МОЖЕТ иметь свою бригаду при приглашении** ✅
2. **Пользователь МОЖЕТ быть в нескольких командах** ✅
3. **Пользователь МОЖЕТ быть владельцем нескольких команд** ✅
4. **При приглашении создается роль "member"** ✅
5. **Существующие роли НЕ изменяются** ✅
6. **Нельзя состоять в команде дважды** ❌

### Когда возникает вопрос:

**"У меня уже есть бригада, что будет если меня пригласят?"**

**Ответ:** Ничего страшного! Вы:
- ✅ Останетесь владельцем своей команды
- ✅ Станете участником новой команды
- ✅ Сможете переключаться между командами
- ✅ Сможете работать в обеих командах параллельно

### Аналогия:

Представьте Discord:
- Вы можете создать свой сервер (владелец)
- Вас могут пригласить на другие серверы (участник)
- Вы видите все сервера в списке
- Вы переключаетесь между серверами

**ProRab работает так же!** 🎉
