# Техническая спецификация продукта ProRab.app
**Версия:** MVP 1.0 → Production Ready  
**Дата документа:** Апрель 2025  
**Платформа:** Веб-приложение (PWA/Mobile-first)

---

## 1. Общая концепция и Цели продукта

**ProRab.app** — это специализированный инструмент управления для малых строительных и ремонтных бригад (2–10 человек), работающих без офиса.

**Ключевое позиционирование:** Не упрощенная версия сложных систем (PlanRadar), а узкоспециализированное решение, закрывающее три конкретные боли:
1.  **Финансовый учет:** Реальная прибыль и расходы ("Где мои деньги?").
2.  **Клиентский сервис:** Быстрая отчетность ("Как красиво отчитаться?").
3.  **Расчеты с командой:** Прозрачная зарплата ("Сколько кому платить?").

**Принцип разработки:** Mobile-first (интерфейс проектируется в первую очередь под смартфоны).

## 2. Архитектура пользователей и Ролевая модель

Это фундаментальная часть логики приложения. Модель должна поддерживать гибкость рынка труда (фриланс/подряд).

### 2.1. Сущность "Бригада" (Team)
*   Бригада — это основная единица группировки данных.
*   У каждой бригады есть **один Владелец** (Прораб).
*   У бригады есть атрибуты: Название, Логотип, Тарифный план.

### 2.2. Роли и Права доступа

| Роль                  | Описание                               | Права и ограничения                                                                                                                                                               | Кол-во бригад                                                              |
| :-------------------- | :------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------- |
| **Владелец (Прораб)** | Создатель аккаунта, плательщик тарифа. | **Полный доступ:** Финансы, Зарплаты, Управление тарифом, Приглашение/Удаление участников, Создание объектов.                                                                     | **Только 1** (своя бригада). Не может быть участником в чужой.             |
| **Участник**          | Наемный рабочий или субподрядчик.      | **Ограниченный доступ:** Видит *только* объекты и задачи той бригады, в которую зашел. Может добавлять расходы и фотоотчеты. **Скрыто:** Прибыль объекта, Зарплаты других, Тариф. | **Безлимитно.** Может состоять в 1, 5 или 20 разных бригадах одновременно. |

### 2.3. Логика "Мульти-бригадности" для Участника
*   **Сценарий:** Пользователь (например, плиточник) работает постоянно в бригаде А, но берет шабашки в бригаде Б и В.
*   **Интерфейс:** В шапке приложения у Участника есть переключатель контекста (Select/Dropdown):
    *   *Текущая: Бригада "Серёга и Ко"*
    *   *Бригада "Димон Строй"*
    *   *Бригада "Колян Север"*
*   При переключении полностью меняется контент (список объектов, задачи), пользователь изолирован в контексте выбранной бригады. Финансы одной бригады не пересекаются с другой.

## 3. Тарификация и Монетизация

Система подписки (SaaS) с рекуррентными платежами (ЮKassa).

**Тарифная сетка:**
1.  **Лайт (490 ₽/мес):** 1 объект, 1 участник (только Прораб). Для одиночек.
2.  **Прораб (990 ₽/мес или 7 900 ₽/год):** До 4 активных объектов, до 3 участников.
3.  **Бригада (1 990 ₽/мес или 12 900 ₽/год):** Безлимит объектов, до 10 участников.

**Спецпредложение (Early Bird):**
*   Для первых 500 пользователей: Вечная цена 990 ₽/мес за тариф «Бригада».
*   Функционал: Выделенный блок на экране оплаты.

## 4. Функциональные требования (Поэкранно)

### 4.1. Авторизация и Онбординг
1.  **Вход:**
    *   Основной метод: **Telegram Auth** (в один клик).
    *   Альтернативный метод: Email + Пароль.
2.  **Онбординг (Wizard, 3 шага):**
    *   Шаг 1: Ввод названия бригады.
    *   Шаг 2: Загрузка логотипа (или выбор из пресетов).
    *   Шаг 3: Автоматическое создание первого объекта с демо-данными (для обучения).

### 4.2. Главный экран (Дашборд)
*   **Список объектов:** Активные — сверху, Архивные — снизу (свернуты).
*   **Карточка объекта (мини):**
    *   Фото + Название + Адрес.
    *   Прогресс-бар (% готовности).
    *   **Финансовый индикатор:** Текущая прибыль (зеленым/красным). *Видит только Прораб.*
    *   Бейдж уведомлений: Количество новых реакций от клиента.
*   **Action Button:** Кнопка «+ Новый объект».

### 4.3. Карточка Объекта (Детально)
**Основные данные:**
*   Название, Адрес, Телефон клиента.
*   Бюджет (Сумма договора).
*   Сроки (Начало — Сдача).
*   % Готовности (Слайдер вручную или авторасчет по задачам).
*   Заметки (текстовое поле).
*   **Функция:** "В архив" (объект перестает считаться в лимит тарифа).

### 4.4. Финансовый Дашборд Объекта (Только для Прораба)
*   **Крупные метрики:**
    *   Сумма договора.
    *   Потрачено всего.
    *   Осталось в бюджете.
    *   **Прибыль (Числа + %):** (Бюджет - Расходы).
    *   Распределение прибыли: "На зарплату бригаде" vs "Чистая прибыль прораба".
*   **Визуализация:** Круговая диаграмма расходов (Материалы, Работа, Логистика и т.д.).

### 4.5. Учет расходов
*   **Доступ:** Кнопка «+ Расход» сквозная (Sticky bottom).
*   **Форма (UX 3-5 секунд):**
    *   Сумма (NumPad).
    *   Категория (Выбор из списка: Материалы, Работа, Инструмент, Аренда, Транспорт, Прочее + Своя категория).
    *   Фото чека (Обязательно, 1-5 фото).
    *   Комментарий (Опционально).
    *   **Чекбокс:** «Оплатил клиент напрямую» (Сумма учитывается в смете, но НЕ вычитается из баланса прораба).
*   **Лента расходов:** Хронологический список, фильтрация по категориям, итоговая сумма.

### 4.6. Фотоотчеты клиенту (Killer Feature №1)
**Создание:**
1.  Прораб выбирает 1-20 фото.
2.  Добавляет комментарий (Текст или Голосовой ввод).
3.  Генерация публичной ссылки.

**Сторона Клиента (Web View, без логина):**
*   URL вида: `https://prorab.app/r/unique_id`
*   Адаптивный дизайн с логотипом бригады.
*   Прогресс-бар объекта.
*   Галерея фото (зум по клику).
*   Текст отчета.
*   Кнопка «Написать прорабу» (Deep link в WhatsApp/Telegram).
*   **Интерактив:** Клиент ставит реакции на фото (❤️, ✅, ❓). Реакции мгновенно отображаются у прораба в приложении.

### 4.7. Зарплата и Команда (Killer Feature №2)
**Управление участниками:**
*   Приглашение через ссылку/QR-код.
*   Настройка профиля участника (Фото, Имя, Роль).

**Модель оплаты (настраивается для каждого):**
1.  % от прибыли.
2.  Фикс за объект.
3.  За м² (Сумма × Площадь).
4.  За день (Сумма × Дни).
5.  Почасовая (Сумма × Часы).

**Закрытие объекта:**
*   Кнопка «Закрыть объект и рассчитать».
*   Система считает итоговые суммы.
*   **Вывод:** Текстовый шаблон для копирования в мессенджер:
    > *Объект [Название] закрыт. Вася: 87 400 ₽, Петя: 74 200 ₽. Итого бригада: 283 500 ₽. Моя прибыль: 361 500 ₽.*

### 4.8. Задачи (Kanban)
*   **Колонки:** Запланировано → В работе → Готово.
*   **Карточка:** Название, Исполнитель (из участников), Дедлайн, Чек-лист.
*   **Автоматизация:** Перенос в «Готово» фиксирует дату завершения (важно для сдельной/почасовой оплаты).
*   **Drag & Drop** интерфейс.

## 5. Технические требования и Стек

### 5.1. Frontend & UX
*   **Mobile-first:** Все элементы управления в зоне доступности большого пальца.
*   **Скорость:** Создание расхода или отчета должно быть мгновенным.
*   **Offline:** В MVP не требуется, но архитектура должна позволять кэширование.

### 5.2. Backend & Data
*   **Хранение фото:** Cloudflare R2 (или аналог S3) — оптимизация расходов.
*   **Безопасность:** Шифрование чувствительных данных (телефоны клиентов, финансовые суммы) в базе данных.
*   **Публичные отчеты:** Доступ только на чтение (Read-only), генерация уникальных токенов для ссылок, отсутствие доступа к остальной части системы через эту ссылку.

### 5.3. Интеграции
*   Telegram API (Auth, Notifications).
*   WhatsApp API (Deep links для отправки сообщений).
*   ЮKassa (Платежный шлюз).
