Вот детально проработанный `roadmap.md` для реализации **ProRab.app** на стеке Next.js + NestJS + GraphQL + PostgreSQL. План составлен с учетом архитектуры ролей и модели «Бригады», описанной выше.

```markdown
# Roadmap разработки ProRab.app (MVP)

Этот документ описывает пошаговый план реализации продукта от инициализации репозитория до полностью функционального MVP.

**Стек:** Monorepo (Turborepo), Next.js 16 (App Router), NestJS 11 (GraphQL), PostgreSQL (TypeORM), SuperTokens, Cloudflare R2.

---

## Этап 1: Инициализация и Фундамент (Дни 1–2)

Цель: Настроить среду разработки, базу данных и базовую структуру монорепозитория.

- [ ] **Инициализация проекта**
    - [x] Создать монорепозиторий с помощью Turborepo.
    - [x] Настроить `apps/web` (Next.js 16 + Tailwind + ShadCN/ui).
    - [x] Настроить `apps/api` (NestJS + GraphQL модуль).
    - [ ] Настроить общие пакеты `packages/ui` и `packages/db`..0

- [ ] **База данных и ORM**
    - [x] Поднять PostgreSQL (локально в Docker или облако Supabase/Railway).
    - [ ] Настроить Prisma в `apps/api`.
    - [ ] Создать базовые миграции и конфиг для подключения.

- [ ] **Настройка GraphQL**
    - [x] Настроить Apollo Server в NestJS (Code First подход).
    - [ ] Настроить генерацию типов для фронтенда (Codegen).
    - [ ] Настроить `TanStack Query` и `GraphQL Client` на фронтенде.

## Этап 2: Авторизация, Пользователи и Бригады (Дни 3–5)

Цель: Реализовать вход в систему, создание профиля и архитектуру "Бригады" (Team).

- [ ] **Auth (SuperTokens)**
    - [ ] Интегрировать SuperTokens в NestJS (Backend).
    - [ ] Настроить SuperTokens на Next.js (Frontend).
    - [ ] Реализовать вход через Email/Password.
    - [ ] Реализовать вход через Telegram (ThirdParty provider).

- [ ] **Сущности БД (Users & Teams)**
    - [ ] Создать сущность `User`.
    - [ ] Создать сущность `Team` (Бригада).
    - [ ] Создать сущность `TeamMember` (связь User <-> Team с ролями).

- [ ] **Бизнес-логика (Backend)**
    - [ ] Реализовать API создания бригады (при регистрации).
    - [ ] Реализовать логику "Переключателя контекста" (получение списка моих бригад).
    - [ ] Настроить Guards: проверка, является ли юзер владельцем или участником.

- [ ] **Интерфейс (Frontend)**
    - [ ] Страница входа/регистрации.
    - [ ] Онбординг (Wizard):
        - [ ] Шаг 1: Ввод названия бригады.
        - [ ] Шаг 2: Загрузка логотипа.
    - [ ] Компонент "Переключатель бригад" в шапке сайта.

## Этап 3: Управление Объектами (Проектами) (Дни 6–7)

Цель: Реализовать CRUD для строительных объектов и ограничения тарифов.

- [ ] **Сущность Project**
    - [ ] Создать Entity `Project` (название, адрес, бюджет, статус, даты).
    - [ ] Связать Project с Team.

- [ ] **API Проектов**
    - [ ] Мутация `createProject` с проверкой лимитов тарифа (Guard).
    - [ ] Квери `myProjects` (фильтрация по текущей активной бригаде).
    - [ ] Мутация `updateProject` и `archiveProject`.

- [ ] **Интерфейс Дашборда**
    - [ ] Главная страница со списком карточек объектов.
    - [ ] Индикаторы на карточке: бюджет, прогресс, статус.
    - [ ] Форма создания/редактирования объекта.
    - [ ] Страница детального просмотра объекта (скелет).

## Этап 4: Учёт Расходов и Медиа (Дни 8–9)

Цель: Реализовать самую частотную функцию — добавление чеков и трат.

- [ ] **Интеграция с Cloudflare R2**
    - [ ] Настроить S3-клиент в NestJS.
    - [ ] Реализовать API загрузки изображений (Upload scalar для GraphQL).

- [ ] **Сущность Expense**
    - [ ] Создать Entity `Expense` (сумма, категория, фото, флаг "оплатил клиент").
    - [ ] Создать справочник категорий.

- [ ] **Функционал расходов**
    - [ ] API добавления расхода с загрузкой фото.
    - [ ] API получения ленты расходов по объекту (пагинация).
    - [ ] Подсчет суммы всех расходов "на лету" или через агрегацию.

- [ ] **Интерфейс расходов**
    - [ ] Кнопка "Добавить расход" (FAB - Floating Action Button).
    - [ ] Форма добавления (оптимизированная под мобильные).
    - [ ] Лента расходов (Timeline view).
    - [ ] Просмотр фото чека (Zoom/Lightbox).

## Этап 5: Фотоотчёты для Клиента (Wow-фича №1) (Дни 10–12)

Цель: Создать генератор публичных веб-страниц для заказчиков.

- [ ] **Сущность PhotoReport**
    - [ ] Создать Entity `PhotoReport` и `ReportPhoto`.

- [ ] **Генерация отчета**
```
