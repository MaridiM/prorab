# Процесс приглашения пользователей в бригаду

## Обзор

Система поддерживает два способа приглашения пользователей в бригаду:
1. **Приглашение по email с кодом** (рекомендуемый способ)
2. **Приглашение по email с magic link** (альтернативный способ)

## Вариант 1: Приглашение по email с кодом (Рекомендуемый)

### Процесс для бригадира

1. **Генерация кода приглашения**
   - Бригадир открывает страницу управления бригадой
   - Нажимает кнопку "Пригласить участника"
   - Выбирает способ приглашения: "По email"
   - Вводит email адрес пользователя
   - Система генерирует **6-значный код приглашения** (например: `ABC123`)
   - Код привязан к конкретной бригаде и имеет срок действия (24-72 часа)

2. **Отправка приглашения**
   - Система отправляет email пользователю с:
     - Информацией о бригаде (название, логотип)
     - 6-значным кодом приглашения
     - Инструкциями по присоединению
     - Ссылкой на страницу ввода кода: `/onboarding/invite`

### Процесс для приглашенного пользователя

1. **Получение приглашения**
   - Пользователь получает email с кодом приглашения
   - В email содержится:
     ```
     Привет!
     
     Вас пригласили присоединиться к бригаде "Название бригады"
     
     Код приглашения: ABC123
     
     Перейдите по ссылке для активации: [ссылка]
     ```

2. **Активация приглашения**
   - Пользователь переходит по ссылке из email или открывает `/onboarding/invite`
   - Открывается страница "Присоединиться к бригаде"
   - Пользователь вводит 6-значный код приглашения
   - Система валидирует код:
     - Проверяет существование кода
     - Проверяет срок действия (не истек ли)
     - Проверяет, не использован ли уже код

3. **Регистрация/Авторизация**
   - Если пользователь **не зарегистрирован**:
     - Система предлагает создать аккаунт
     - Пользователь вводит имя, email, пароль
     - После регистрации автоматически присоединяется к бригаде
   - Если пользователь **уже зарегистрирован**:
     - Система проверяет email из приглашения
     - Если email совпадает - автоматически присоединяет к бригаде
     - Если email не совпадает - требует авторизации

4. **Завершение процесса**
   - Пользователь автоматически становится участником бригады
   - Получает роль "MEMBER" (участник)
   - Перенаправляется в интерфейс бригады
   - **НЕ проходит** онбординг по созданию своей бригады

## Вариант 2: Приглашение по email с magic link (Альтернативный)

### Процесс для бригадира

1. **Генерация magic link**
   - Бригадир открывает страницу управления бригадой
   - Нажимает "Пригласить участника"
   - Выбирает "По email с ссылкой"
   - Вводит email адрес пользователя
   - Система генерирует уникальную ссылку с токеном:
     ```
     https://prorab.space/onboarding/invite?token=abc123xyz789&email=user@example.com
     ```
   - Ссылка имеет срок действия (24-72 часа)

2. **Отправка приглашения**
   - Система отправляет email с magic link
   - Email содержит:
     ```
     Привет!
     
     Вас пригласили присоединиться к бригаде "Название бригады"
     
     Нажмите на ссылку для активации: [magic link]
     ```

### Процесс для приглашенного пользователя

1. **Получение приглашения**
   - Пользователь получает email с magic link
   - Нажимает на ссылку в email

2. **Активация приглашения**
   - Система автоматически:
     - Проверяет токен из URL
     - Проверяет срок действия
     - Определяет бригаду из токена
   - Если токен валиден:
     - Автоматически присоединяет пользователя к бригаде
     - Если пользователь не зарегистрирован - предлагает регистрацию
     - Если зарегистрирован - автоматически присоединяет

## Сравнение вариантов

| Критерий | Код приглашения | Magic link |
|----------|----------------|------------|
| **Безопасность** | ✅ Высокая (код можно проверить) | ⚠️ Средняя (токен в URL) |
| **Удобство** | ⚠️ Требует ввода кода | ✅ Один клик |
| **Гибкость** | ✅ Можно передать устно/в мессенджере | ⚠️ Только по email |
| **Отслеживание** | ✅ Легко отследить использование | ⚠️ Сложнее отследить |
| **Рекомендация** | ✅ **Рекомендуется** | ⚠️ Альтернатива |

## Техническая реализация

### GraphQL мутации

```graphql
# Создание кода приглашения
mutation CreateInviteCode($teamId: String!) {
  createInviteCode(teamId: $teamId) {
    id
    code
    expiresAt
    createdAt
  }
}

# Присоединение по коду
mutation JoinTeamByInvite($code: String!) {
  joinTeamByInvite(code: $code) {
    id
    name
    logo
    iconId
    members {
      id
      role
    }
  }
}

# Валидация кода (перед присоединением)
query ValidateInviteCode($code: String!) {
  validateInviteCode(code: $code) {
    isValid
    team {
      id
      name
      logo
    }
    expiresAt
  }
}
```

### Модель данных

```prisma
model InviteCode {
  id        String   @id @default(uuid())
  teamId    String   @map("team_id")
  code      String   @unique  // 6 символов: A-Z, 0-9
  expiresAt DateTime @map("expires_at")
  usedBy    String?  @map("used_by")
  usedAt    DateTime? @map("used_at")
  createdAt DateTime @default(now()) @map("created_at")

  team Team @relation(fields: [teamId], references: [id], onDelete: Cascade)

  @@index([teamId])
  @@index([code])
  @@map("invite_codes")
}
```

### Валидация кода

- Формат: ровно 6 символов
- Допустимые символы: A-Z (заглавные буквы), 0-9 (цифры)
- Примеры: `ABC123`, `XYZ789`, `123456`
- Автоматическое преобразование в верхний регистр

## UI/UX Flow

### Страница ввода кода (`/onboarding/invite`)

1. **Заголовок**: "Присоединиться к бригаде"
2. **Описание**: "Введите код приглашения, который вам отправили"
3. **Поле ввода**:
   - Большое поле с моноширинным шрифтом
   - Автоматическое преобразование в верхний регистр
   - Максимум 6 символов
   - Placeholder: "ABC123"
4. **Кнопки**:
   - "Назад" - возврат на главную страницу онбординга
   - "Присоединиться" - активация кода
5. **Подсказка**: "Код приглашения можно получить у владельца бригады"

### Валидация в реальном времени

- Проверка формата (6 символов, A-Z, 0-9)
- Проверка существования кода (опционально, через `validateInviteCode`)
- Отображение ошибок:
  - "Код должен содержать 6 символов"
  - "Код недействителен или истек"
  - "Код уже использован"

## Безопасность

1. **Срок действия кода**: 24-72 часа (настраивается)
2. **Одноразовость**: код можно использовать только один раз
3. **Привязка к бригаде**: код работает только для конкретной бригады
4. **Валидация на сервере**: все проверки выполняются на backend
5. **Rate limiting**: ограничение количества попыток ввода кода

## Рекомендации

✅ **Использовать код приглашения** для:
- Приглашений через мессенджеры (Telegram, WhatsApp)
- Устных приглашений
- Приглашений через SMS
- Когда нужен контроль над использованием кода

⚠️ **Magic link можно использовать** для:
- Быстрых приглашений по email
- Когда удобство важнее безопасности
- Когда не требуется отслеживание использования
