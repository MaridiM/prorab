# Backend i18n (NestJS + i18next)

- Библиотеки: `i18next`, `i18next-fs-backend`, `i18next-http-middleware`.
- Локали: `apps/api/src/core/i18n/locales/{en,ru}/{auth,common,mail,sms}.json`.
- Язык по умолчанию: `en`; доступные языки вычисляются из папок локалей (`LANGUAGES`).
- Cookie для языка: `language` (читается в декораторе/пайпе и middleware).

## Конфигурация

- Инициализация: `apps/api/src/core/config/i18n.config.ts`
  - `initI18n()` → `i18next.use(Backend).use(LanguageDetector).init(...)`.
  - Файлы: `loadPath = src/core/i18n/locales/{{lng}}/{{ns}}.json`.
  - Детектирование: querystring → cookie → header.
  - `saveMissing` в dev; `missingKeyHandler` пишет отсутствующие ключи в локали + логгер.
  - Экспортирует singleton `i18n`.
- Константы: `apps/api/src/core/i18n/i18n.constants.ts`
  - `LANGUAGES`, `DEFAULT_LANGUAGE`, `LOCALE_DIR`, `LOCALE_FILE_PATH`, `NAMESPACES`.
  - В dev предупреждает об отсутствующих папках локалей.
- Модуль: `apps/api/src/core/i18n/i18n.module.ts`
  - @Global, провайдер `I18N_CORE` (singleton i18next), `I18nService`.
  - Вызывает `initI18n()` в фабрике.
- Сервис: `apps/api/src/core/i18n/i18n.service.ts`
  - Типизированные `t`, `getFixedT`, `raw`, `rich`, `exists`, `dir`.
  - Статические аналоги для использования без DI.
- Декоратор: `@Lang()` (`apps/api/src/core/i18n/decorators/lang.decorator.ts`)
  - Достаёт язык в порядке: cookie.language → req.language → Accept-Language → `en`.
- Валидация: `I18nValidationPipe` и helper `t(...)` (`apps/api/src/core/i18n/validation/*`)
  - Pipe вытаскивает язык из cookie/req/header и кладёт в context для class-validator.
  - Helper `t('auth.errors.user_not_found')` отдаёт функцию сообщения с подстановками.
- Логгер: `apps/api/src/core/i18n/logging/i18n.logger.ts`
  - Пишет `logs/i18n/{missing-keys, ...}.{log,json,csv}` для пропущенных/дублирующихся ключей.

## Встраивание в приложение

- `apps/api/src/main.ts`
  - Перед созданием Nest: `await initI18n()`.
  - Middleware: `i18nextMiddleware.handle(i18n)` добавляет `req.i18n`/`req.language`.
  - Фоллбек языка при JSON парсинге: заполняет `req.language` из Accept-Language → DEFAULT_LANGUAGE.
  - Глобальный `ValidationPipe` + `sessionConfig` + CORS; язык также использует cookie `language`.

## Шаблоны использования

### 1) Резолвер/сервис с типизированным `t`
```ts
// apps/api/src/modules/auth/2fa/resolvers/2fa.resolver.ts
import { I18nService, Lang, Language } from '@/core/i18n'

@Resolver()
export class TwoFAResolver {
  constructor(private readonly i18n: I18nService) {}

  @Mutation(() => Boolean)
  async disable2fa(@Lang() lng: Language) {
    // ...
    throw new ForbiddenException(
      this.i18n.t('auth.errors.2fa.method_not_found', { lng, defaultValue: '2FA method not found' }),
    )
  }
}
```

### 2) Валидация с локализованными сообщениями
```ts
// apps/api/src/core/i18n/validation/i18n-validation.helper.ts
import { t } from '@/core/i18n'

class LoginInput {
  @MinLength(6, { message: t('auth.errors.password.too_short', { min: 6 }) })
  password: string
}
// Pipe возьмёт язык из cookie/headers и передаст в context.lang
```

### 3) Типизированные шаблоны писем (React Email)
```tsx
// apps/api/src/core/provider/mail/templates/authentication/reset-password.template.tsx
export function ResetPasswordTemplate({ url, metadata, i18n, lng = 'en' }: Props) {
  const t = i18n.t('mail.reset_password', { lng })
  return (
    <TemplateWrapper template="reset_password" lng={lng} i18n={i18n}>
      <Heading>{t('title')}</Heading>
      <Text>{t('description')}</Text>
      <Button href={url}>{t('button_text')}</Button>
    </TemplateWrapper>
  )
}
```

## Как добавить/обновить переводы
1. Добавьте ключи в `src/core/i18n/locales/{en,ru}/<namespace>.json`.
2. Если нужен новый namespace, создайте файл в обеих локалях и убедитесь, что `NAMESPACES` его видит (имена файлов `.json`).
3. Для модульных словарей обновите типы, если используются в коде, чтобы автодополнение не ломалось.
4. В dev пропущенные ключи записываются в `logs/i18n/missing-keys.*`; перенесите их в JSON и удалите из логов.
